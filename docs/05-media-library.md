# 05 — Pustaka Media (File Management Terpusat)

Terinspirasi pola "centralized file model" (satu model/tabel untuk semua berkas) dan pengalaman media WordPress: unggah sekali, pilih/pakai ulang di mana saja.

## Prinsip

1. **Satu pintu masuk.** Semua unggahan lewat `POST /admin/media` → `MediaService::store()`. Controller modul lain **tidak** menangani upload.
2. **Referensi berupa path.** Kolom di model lain (mis. `posts.cover_image`) tetap menyimpan string path yang sama dengan `media.path`. Tidak ada FK/pivot, sehingga data lama tetap valid dan halaman publik tidak berubah.
3. **Berkas bersama.** Satu media boleh dipakai banyak record, maka menghapus record **tidak** menghapus berkas; berkas hanya hilang saat dihapus dari Pustaka Media.
4. **Aman dihapus.** Media yang masih dipakai tidak dapat dihapus (lihat "Pelacakan pemakaian").

## Pemrosesan unggahan

| Jenis                     | Perlakuan                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Gambar (JPG/PNG/WebP/GIF) | Skala turun maks 1920×1920, encode WebP kualitas 80, kompres hingga ≤ ~400 KB. Lebar/tinggi dicatat. Varian responsif `<nama>-<lebar>w.webp` (WebP kualitas 75, rasio asli, tanpa crop; EXIF dibuang saat re-encode) dibuat sinkron saat unggah untuk setiap lebar di `config/media.php` (`variant_widths`: 320, 480, 640, 750, 1024, 1280, 1600) yang **lebih kecil** dari gambar tersimpan; gambar kecil tidak diperbesar dan tidak ada berkas kembar. GIF animasi menjadi gambar diam (frame pertama), perilaku yang sudah ada. |
| PDF                       | Disimpan apa adanya.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

Penyimpanan: disk `public` (lokal) atau bucket S3-compatible bila dipilih di Pengaturan Sistem (lihat "Penyimpanan S3"), folder `media/YYYY/MM/`, nama berkas **kebab-case**: slug nama asli + akhiran acak 8 karakter huruf kecil/angka (contoh `Foto Profil 2024.JPG` → `media/2026/10/foto-profil-2024-a1b2c3d4.webp`; nama kosong/tak valid → `file-<acak>`). Ekstensi huruf kecil; gambar selalu `.webp`. Nama asli tetap disimpan di kolom `media.name`. URL publik `/storage/<path>` via `ImageService::url()`.

## Penyimpanan S3

Kelompok **Penyimpanan Media** di `/admin/system-settings` (`SystemSettingGroup::Storage`) memilih `local` atau bucket S3-compatible (AWS S3, Cloudflare R2, MinIO, Wasabi, DO Spaces): endpoint, region, bucket, access key & secret (terenkripsi, tidak pernah ditampilkan kembali), URL publik/CDN, dan path-style. Disk `media_s3` dibangun saat runtime oleh `MediaStorage` dari pengaturan (tanpa ubah `.env`/deploy; dependensi `league/flysystem-aws-s3-v3`).

- Unggahan baru ditulis ke disk aktif dan dicatat di `media.disk`; `ImageService::url()` memakai URL publik bucket (URL publik/CDN, atau diturunkan dari endpoint + bucket). Bucket harus dapat dibaca publik; berkas ditulis tanpa ACL.
- Saat menyimpan dengan driver `s3`, koneksi diuji (tulis, baca, hapus berkas uji). Bila gagal, driver otomatis dikembalikan ke `local` dan situs tetap aman. Tombol "Uji koneksi" menguji pengaturan yang sudah tersimpan.
- Beralih ke `s3` (koneksi lolos) mengantre `SyncMediaStorageJob` yang menyalin berkas lama ke bucket (butuh `queue:work`; tanpa worker, jalankan manual). Manual: `php artisan media:sync-storage` (menyalin asli, thumbnail, dan semua varian ke disk aktif, lalu mengubah `media.disk`; `--delete-source` menghapus salinan lama; aman diulang). Tanpa 404 selama sinkronisasi: `MediaStorage::url()` memakai disk milik tiap record, jadi berkas yang belum tersalin tetap dilayani dari lokal dan otomatis beralih ke URL bucket begitu record-nya selesai disalin (daftar record tertinggal di-cache dan dibersihkan tiap record selesai). `ContentImageOptimizer` menulis ulang `src` gambar di isi artikel ke URL terkini saat render, tanpa mengubah HTML di database. URL lama `/storage/<path>` yang masih tersimpan di HTML/tautan luar diarahkan 302 ke bucket oleh `MediaRedirectController` bila berkasnya tidak ada lagi di lokal (mis. setelah `--delete-source`); hanya path media yang dikenal yang diarahkan. Ini mensyaratkan web server meneruskan berkas yang tidak ada ke `index.php` (bawaan Laravel) dan disk `local` tidak lagi memakai `serve` (dinonaktifkan di `config/filesystems.php`; rute `storage/{path}` miliknya bentrok).
- Menonaktifkan bucket (driver kembali `local`) mengantre job yang sama untuk menyalin balik berkas dari bucket ke lokal (salinan di bucket tidak dihapus). Setelah **semua** record berpindah (bila ada yang gagal, konten tidak disentuh), `MediaContentUrlRewriter` menukar URL gambar di kolom rich text (`posts.content`, `notes.content`, `clarifications.content`, `portfolios/services.description`, `users.bio`, beserta kolom `_en`) antara `/storage/media/…` dan URL bucket, sehingga HTML tersimpan dan editor menunjuk ke penyimpanan aktif. Perintah `media:sync-storage` melakukan hal yang sama.
- Gambar di dalam HTML artikel yang berisi URL `/storage/...` lama tetap dikenali `ContentImageOptimizer`; URL bucket juga dikenali.
- Pemeriksaan keberadaan thumbnail ke bucket (`thumbnailUrl`) di-cache 1 hari karena berupa panggilan jaringan.
- Lampiran email balasan dibaca lewat disk milik record `media`.

## Rute

`GET admin/media` · `GET admin/media/browse` (JSON, `?search=&type=image|document&page=`) · `POST admin/media` (`file`) · `PUT admin/media/{media}` · `DELETE admin/media/{media}`

## Pelacakan pemakaian

`MediaService::USAGES` memetakan `tabel → kolom exact` (path sama persis) dan `kolom like` (path tertanam di HTML: `posts.content`, `portfolios.description`, `services.description`; `services.image` kolom exact). **Saat menambah kolom berkas baru di model mana pun, daftarkan di `USAGES`** dan pakai `MediaField` + `new MediaPath($this->route('...')?->kolom)` di FormRequest.

## Menambah field berkas ke model baru (resep)

1. Kolom `string` (nullable bila opsional) di migrasi `create_*`.
2. FormRequest: `'kolom' => ['required|nullable', 'string', new MediaPath($this->route('model')?->kolom)]`.
3. Form Svelte: `<MediaField name="kolom" value={item.kolom} accept="image" />`.
4. Tambahkan ke `MediaService::USAGES`.
5. Controller: cukup `$request->validated()`; tidak ada logika upload.
6. Tes: buat `Media::factory()->create()` dan kirim `->path`.

## Batasan yang diketahui

- Belum ada folder/kategori media atau versi/ganti berkas. Varian responsif dihasilkan lewat `ImageService::createVariants()`; `Media::srcset` (accessor, ikut JSON) dan `ContentImageOptimizer` membangun `srcset` dari `media.variants` (media lama tanpa varian jatuh balik ke thumbnail 640 px bila ada, atau gambar polos). `ImageService::thumbnailUrl()` dipakai payload kartu (beranda, daftar blog, portofolio, kedai kopi) dan jatuh balik ke gambar asli bila thumbnail tidak ada; media lama diisi lewat `php artisan media:variants` (`--force` untuk membuat ulang; nama berkas deterministik sehingga aman dijalankan ulang; menggantikan `media:thumbnails`). Seluruh varian ikut terhapus saat media dihapus.
- Gambar di dalam isi artikel/portofolio/catatan/klarifikasi/layanan diproses `ContentImageOptimizer` setelah `HtmlSanitizer` (lebar/tinggi dari tabel `media`, `loading="lazy"`, `decoding="async"`, `srcset`/`sizes` dari varian bila ada); sampul artikel memakai `ContentImageOptimizer::cover()`.
- Pelacakan pemakaian berbasis pemindaian kolom, bukan relasi; kolom tak terdaftar tidak terlindungi.
- Belum ada pembersihan media yatim otomatis.
- `system_settings.seo_image` menyimpan path di kolom terenkripsi sehingga tidak terpindai `USAGES`; media itu bisa terhapus dari Pustaka Media tanpa peringatan (SEO jatuh balik ke gambar bawaan hanya bila setting dikosongkan).

## Seeder

Seeder yang membawa gambar (`EducationSeeder`, `CoffeePlaceSeeder`, `PortfolioSeeder`, `PostSeeder` dengan sampel `public/images/posts/*.webp`) mendaftarkan berkas bawaan `public/images/...` lewat `MediaService::storeFromPublicPath()`, sehingga gambar tampil di Pustaka Media dan kolom modelnya menyimpan `media.path` hasilnya (diproses WebP seperti unggahan biasa).
